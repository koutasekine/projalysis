# プロジェクト分析

プロジェクト計画([plan.sapp.jp](https://plan.sapp.jp))の `.plan` を複数読み込み、計画の変更を表と図で示すブラウザアプリです。
`index.html` 1 ファイルで動き、インストールやアカウントは要りません。外部のサービスを使わず、データをどこにも送信しません。

- `.plan` を `version:`(保存日)の順に並べ、計画の改訂履歴を示す
- すべての版の概要と推移(終了日、バーンアップ、タスク数とタスクの進捗、変更の多い部分、担当者ごとの作成の日数)を示す
- 選んだ 2 つの版の差(タスクの追加・削除・移動・変更、終了日の差、FBS・PBS・MOP の変更、メンバーの変更)を示す
- 表はタブ区切りでコピーでき、表と図は 1 つずつ SVG・PNG で保存できる
- 読み込んだ版を `.plans` 1 つにまとめて保存できる
- すべてのビューを PDF にまとめて印刷できる

## 使い方

公開版は https://projalysis.sapp.jp で使えます。ダウンロードした `index.html` を直接開いても使えます。

1. 公開版か `index.html` を、ブラウザ(Edge・Chrome など)で開きます。
2. 「開く」か、ファイルを画面に置いて `.plan` を読み込みます。複数をまとめて読み込めます。
3. 比較のビューでは、ビューの上の帯で比較する版(変更前・変更後)を選びます。最初は一覧の最初と最後です。帯は、比較できる版が 2 つ以上あるときに出ます。選択欄の隣のプリセット「初版 → 最新版」「前の版 → 最新版」で、よく使う組をすぐに選べます。
4. 「ビュー」で表と図を切り替えます。

比較の規則は、画面の「使い方」で見られます。

## 比較の規則

- FBS・PBS・WBS の要素は、根を除いた名前の並び(`設計フェーズ::画面設計` など)で対応づけます。担当者は名前で対応づけます。
- 名前を変えた要素は「削除」と「追加」の 2 行になります。似た名前の推測はしません。
- 同じ名前で親だけが変わった要素は「移動」になります(同じ名前が 1 つずつのときだけ)。
- 根は名前によらず対応づけ、名前の変更を 1 行で示します。
- タスクの変更は、日数・作成者・確認者・対象・先行・メモの違いです(作成者・確認者・対象は親から受け継いだ値)。進捗が変わったタスクは別に示します。
- 終了日は、各版のテキストから計算した日付です(`.plan` に実績の日付はありません)。差は暦日です。
- `.plan` の解析と日程の計算は、プロジェクト計画と同じ計算部で行います。
- エラーのある版と `version:` のない版は、比較から除外します。

## ビュー

| ビュー | 内容 |
|---|---|
| 概要 | すべての版を列に並べた表(日程、メンバー数、FBS・PBS・WBS の要素数、タスク数、総日数、MOP の総数と確認した数、警告数など)。左の版から変わった値は太字 |
| 改訂履歴 | すべての版の変更を 1 行ずつ、対象(タスク・タスクの進捗・FBS 要素・PBS 要素・MOP・根の名前・開始日・期限・全体の休み・メンバー・メンバーの休み・終了日)と操作(追加・削除・移動・変更など)の列に分けて示す表。機能やテストを追加した版が分かる。除外した版は警告で示す。行を押すと、その版と一つ前の版を比較する |
| 推移 | すべての版の図: 終了日の推移、バーンアップ(横軸は版の日付)、タスク数と進捗の推移、変更の多い部分(WBS の第 1 層ごと)、担当者ごとの作成の日数。下に、タスクの進捗が初めて変わった版の表。図の版を押すと、その版と一つ前の版を比較する |
| WBS | 追加・削除・移動・変更したタスクと、進捗が変わったタスク(WBS の途中の要素の増減は、対応した要素の数にだけ表れる) |
| 日程 | タスクごとの終了日(変更前・変更後)と差。最も遅れたタスク。見積もりの変化(タスクごとの日数の変更前・変更後)と計画外のタスクの割合 |
| FBS・PBS・MOP | FBS・PBS 要素の追加・削除・移動(FBS 要素には MOP を添える)。MOP の追加・削除・確認・確認の取り消し |
| メンバー | メンバーの追加・削除、担当者ごとの作成の日数の変化、メンバーの休みの変更 |
| ガントチャート | 2 つの版のガントチャートの比較(変更前は灰、変更後は黒枠)と、担当者別ガントチャートの比較 |

図はどれも、各版の時点の計画の推移です(実績ではありません)。完了の時期は、初めて完了になった版とその前の版の日付の間として示します。

## 保存と読み込み

| 操作 | 内容 |
|---|---|
| 開く / ドラッグ & ドロップ | `.plan`、`.plans`、プロジェクト計画の版 0.30 までに保存した `.svg` を一覧に足す(版 0.31 以降の SVG にはテキストが入っていないので読めない) |
| 上書き保存(Ctrl+S) | 開いている `.plans` に上書きする。まだファイルがないときは保存先を選ぶ |
| 別名で保存 | 保存先とファイル名を選んで、一覧を `.plans` に保存する |
| コピー(表の題の右) | その表をタブ区切りの文字でコピーする |
| SVG・PNG(表の題の右) | その表を 1 つ保存する。題は入れない(報告書では題を表の上に書く) |
| SVG・PNG(図の題の右) | 推移・日程・ガントチャートのビューで、その図を 1 つ保存する |
| PDF(図・表の題の右) | その図または表だけを、同じ大きさの紙で印刷する。印刷の画面で「PDF に保存」を選ぶと、余白のない PDF になり、TeX などにそのまま貼れる。保存した SVG をブラウザで開いて印刷しても同じ大きさになる |
| 印刷 / PDF | 全部のビューを横向きで印刷する(比べられる版が 2 つ未満なら概要だけ)。印刷の画面で「PDF に保存」を選ぶと PDF になる。大きな表は行(概要は列)で区切ってページを分ける |
| 新規 | 一覧を空にする |

- テキストが同じ `.plan` は 2 回足しません。
- 保存する SVG・PNG には読み込んだ版を埋め込みません。一覧を残すのは `.plans` だけです。
- 上書きの先は、空の一覧に開いた `.plans` です。そこに別の `.plans` を足した後の最初の上書き保存では、足した版も書き込むことを確かめます。
- Chrome と Edge では、開いたファイルにそのまま上書きします。ほかのブラウザでは、ダウンロードとして保存します。
- 一覧は、このブラウザの `localStorage` にも自動で保持されます(どこにも送信されません)。保持先はブラウザごと、サイトごとです。残したい一覧は、ファイルに保存してください。

## 動作環境

Edge・Chrome などの最近のブラウザで動きます。印刷 / PDF と、図・表の「PDF」は Chrome・Edge で使ってください(Safari では紙の大きさや余白が指定どおりにならないことがあります)。ネット接続が必要なのは公開版のページを開くときだけで、ダウンロードした `index.html` は接続しなくても動きます。

## ファイル

| パス | 内容 |
|---|---|
| `index.html` | アプリ本体。これ 1 つで動く(使うだけなら、ほかのファイルは要らない) |
| `dev/` | `index.html` を組み立てる元のファイル(開発用)。アプリを使うだけなら要らない |
| `dev/core.js` | プロジェクト計画の計算部(core.js)の写し。書き換えない |
| `dev/diff.js` | 比べる処理と表。画面の処理を使わず、Node でも `require('./dev/diff.js')` で読める |
| `dev/ui.js` | 画面の処理 |
| `dev/usage.html` | 画面の「使い方」の中身 |
| `dev/build.py` | `dev/` のファイルから `index.html` を組み立てる(リポジトリのルートで `python3 dev/build.py`)。`python3 dev/build.py sync` で隣の `../plan/dev/core.js` から `dev/core.js` を写し直し、`python3 dev/build.py check` で写しが同じかを調べる |
| `docs/spec.md` | 仕様書 |
| `test/diff_test.cjs` | 比べる処理の検査(`node test/diff_test.cjs`) |
| `test/ui_test.py` | 画面の検査。Python の playwright と Chromium で動かす(`python3 test/ui_test.py [画像の出力先]`) |
| `test/*.plan` | 検査の入力(架空の計画) |
