# プロジェクト分析

プロジェクト計画([plan.sapp.jp](https://plan.sapp.jp))の計画書(`.plan`)と、チーム全員のマイログ([mylog.sapp.jp](https://mylog.sapp.jp) の `.mylog`)を読み、計画書の変更と、チームの作業の進み具合を表と図で示すブラウザアプリです。
`index.html` 1 ファイルで動き、インストールやアカウントは要りません。外部のサービスを使わず、データをどこにも送信しません。読むだけのアプリで、計画書とマイログは書き換えません。

- **計画書分析**(計画書だけで使える): 計画書を `version:`(保存日)の順に並べ、改訂履歴、すべての版のサマリーと推移、選んだ 2 つの版の差を示す
- **作業分析**(マイログを読み込むと出る): 計画書に書き写す候補、問題の兆候(要確認)、依頼と返事の突き合わせ、作業時間・進捗・負荷・影響を受けるタスク・TRL・TPM・テスト・MOP の達成状況を示す
- 表はタブ区切りでコピーでき、表と図は 1 つずつ SVG・PNG・PDF で保存できる
- 読み込んだ計画書とマイログを `.plans` 1 つにまとめて保存できる
- すべてのビューを PDF にまとめて印刷できる

## ほかのアプリとの関係

プロジェクト分析は、[プロジェクト計画](https://plan.sapp.jp)の計画書(`.plan`)を読んで使います。計画書は必ず要ります。[マイログ](https://mylog.sapp.jp)のマイログ(`.mylog`)は任意で、足すと作業分析が出ます。計画書とマイログは読むだけで、書き換えません。

どのアプリをどう組み合わせるかは、プロジェクトを運営する人が決めます。プロジェクト分析を使う組み合わせの例:

- 計画とプロジェクト分析: 計画書を直すたびに保存して版を重ね、改訂の履歴と推移を見る
- 3 つとも: 各自のマイログをプロジェクト分析に集めて進み具合と問題の兆候を見、反映候補をもとに計画書を直して新しい版を保存する

## 使い方

公開版は https://projalysis.sapp.jp で使えます。ダウンロードした `index.html` を直接開いても使えます。

1. 公開版か `index.html` を、ブラウザ(Edge・Chrome など)で開きます。
2. 「ファイルを追加」か、ファイルを画面に置いて、計画書(`.plan`)と、使うときは全員のマイログ(`.mylog`)を読み込みます。複数をまとめて読み込めます。
3. 「ビュー」で表と図を切り替えます。選択欄は、サマリー、作業分析のまとまり(マイログがあるときだけ)、計画書分析のまとまりの順です。
4. 計画書分析の 2 つの版を比べるビューでは、ビューの上の帯で比較する版(変更前・変更後)を選びます。作業分析とサマリーでは、ビューの上の帯の「基準日」で、何日までの記録で集計するかを変えられます(既定は今日。計画書も、基準日以前の日付の版のうち、いちばん新しい版を使う)。
5. 「別名で保存」で `.plans` に保存します。次は「開く」でその `.plans` を開けば、同じ一覧から見られます。

plans を開いたときと「例を読み込む」のときは、計画への反映候補があれば反映候補を、なければ要確認を、どちらもなければサマリーを開きます。
初めて開いたときは空です。「例を読み込む」を押すと、カレンダーアプリの開発の例(2 つの版の計画書と、3 人のマイログ)が入ります。例の日付は、読み込んだ日がプロジェクトの途中になるようにずらして入れます。

## ビュー

| まとまり | ビュー | 内容 |
|---|---|---|
| ― | サマリー | すべての版を列に並べた表(日程、メンバー数、FBS・PBS・WBS の要素の数、タスク数、総日数、MOP の総数とチェック済みの数、警告数など。左の版から変わった値は太字)。マイログがあるときは、その下に作業の概要(反映候補・要確認・タスクの区分・作業時間・依頼・MOP の数) |
| 作業分析 | 計画への反映候補 | 計画書に書き写す候補(進捗の変更、MOP のチェックとその取り消し、計画にない作業) |
| 作業分析 | 要確認 | 記録の形から拾った問題の兆候(S1〜S9)。同じ人のマイログが 2 つあるとき、エラーで除外したマイログ、`week:` がそろっていないときの知らせ |
| 作業分析 | 週のまとめ | 選んだ週のチーム全員の記録(メンバーごとの記録日数と合計時間、完了したタスク、作業時間、問題と解決、依頼と返事、メモ、テスト・TRL・TPM) |
| 作業分析 | 依頼 | 受けた依頼の表(人ごとの対応済み・未対応・差し戻し)と、依頼の一覧 |
| 作業分析 | 負荷 | メンバーごとの、完了していない担当のタスクの件数と計画の日数、遅延・問題発生の件数、先週と今週の作業時間 |
| 作業分析 | 進捗 | タスクごとの区分(遅延・問題発生・開始予定日を過ぎた未着手・実行中・開始予定日がまだ先・完了)、始めた日、完了した日、最後の進捗と進捗率 |
| 作業分析 | 影響を受けるタスク | 遅れているタスクの後ろに、計画書の `after:` でつながるタスク(直接・間接) |
| 作業分析 | 作業時間(人) | 人 × 週の作業時間の表と折れ線の図 |
| 作業分析 | 作業時間(タスク) | 記録先 × 週の作業時間の表。WBS 番号、計画の日数、作業日数を並べる |
| 作業分析 | TRL・TPM | 機能ごとの TRL の推移(表と図)と TPM の推移(表) |
| 作業分析 | テストの記録 | テストごとの新/再・機能・MOP・実施日・結果・記録者 |
| 作業分析 | MOP の達成状況 | すべての MOP の、最後のテストの結果(ok・ng・未実施)とテストした回数 |
| 計画書分析 | 改訂履歴 | すべての版の変更を 1 行ずつ、対象(タスク・タスクの進捗・FBS の要素・PBS の要素・MOP・根の名前・開始日・期限・全体の休み・メンバー・メンバーの休み・終了日)と操作(追加・削除・移動・変更など)の列に分けて示す表。機能やテストを追加した版が分かる。除外した版は警告で示す。行を押すと、その版と一つ前の版を比較する |
| 計画書分析 | 推移 | すべての版の図: 終了日の推移、バーンアップ(横軸は版の日付)、タスク数と進捗の推移、変更の多い部分(WBS の第 1 層ごと)、担当者ごとの作成の日数。下に、タスクの進捗が初めて変わった版の表。図の版を押すと、その版と一つ前の版を比較する |
| 計画書分析 | WBS | 追加・削除・移動・変更したタスクと、進捗が変わったタスク(WBS の途中の要素の増減は、対応した要素の数にだけ表れる) |
| 計画書分析 | 日程 | タスクごとの終了予定日(変更前・変更後)と差。最も遅れたタスク。見積もりの変化(タスクごとの日数の変更前・変更後)と追加したタスクの割合 |
| 計画書分析 | FBS・PBS・MOP | FBS・PBS の要素の追加・削除・移動(FBS の要素には MOP を添える)。MOP の追加・削除・チェック・チェックの取り消し |
| 計画書分析 | メンバー | メンバーの追加・削除、担当者ごとの作成の日数の変化、メンバーの休みの変更 |
| 計画書分析 | ガントチャート | 2 つの版のガントチャートの比較(変更前は灰、変更後は黒枠)と、担当者別ガントチャートの比較 |

計画書分析の図はどれも、各版の時点の計画の推移です(実績ではありません)。完了の時期は、初めて完了になった版とその前の版の日付の間として示します。

## 計画書分析の比較の規則

- FBS・PBS・WBS の要素は、根を除いた名前の並び(`設計フェーズ::画面設計` など)で対応づけます。メンバーは名前で対応づけます。
- 名前を変えた要素は「削除」と「追加」の 2 行になります。似た名前の推測はしません。
- 同じ名前で親だけが変わった要素は「移動」になります(同じ名前が 1 つずつのときだけ)。
- 根は名前によらず対応づけ、名前の変更を 1 行で示します。
- タスクの変更は、日数・作成者・確認者・対象・先行・メモの違いです(作成者・確認者・対象は親から受け継いだ値)。進捗が変わったタスクは別に示します。
- 終了日は、各版のテキストから計算した日付です(`.plan` に実績の日付はありません)。差は暦日です。
- `.plan` の解析と日程の計算は、プロジェクト計画と同じ計算部で行います。
- エラーのある版と `version:` のない版は、比較から除外します。

## 保存と読み込み

| 操作 | 内容 |
|---|---|
| 開く・ファイルを追加 / ドラッグ & ドロップ | `.plans` は、計画書の一覧とマイログの一覧を、その中身で入れ替える。`.plan`・`.txt`(とプロジェクト計画の版 0.30 までに保存した `.svg`)は計画書の一覧に、`.mylog` はマイログの一覧に足す。同じ人(`by:`)のマイログを足すと、「置き換える」「両方残す」「やめる」を尋ねる |
| 上書き保存(Ctrl+S) | 開いている `.plans` に上書きする。まだファイルがないときは保存先を選ぶ(ファイル操作機能のないブラウザでは、ファイル名があれば同じ名前でダウンロードする) |
| 別名で保存 | 保存先とファイル名を選んで、2 つの一覧を `.plans` に保存する(マイログがないときは計画書だけの `.plans`) |
| コピー(表の題の右) | その表をタブ区切りの文字でコピーする |
| SVG・PNG(図・表の題の右) | その図か表を 1 つ保存する。表には題を入れない(報告書では題を表の上に書く) |
| PDF(図・表の題の右) | その図または表だけを、同じ大きさの紙で印刷する。印刷の画面で「PDF に保存」を選ぶと、余白のない PDF になり、TeX などにそのまま貼れる |
| 印刷 / PDF | 全部のビューを印刷する(サマリーと計画書分析は横向き、作業分析は縦向き)。印刷の画面で「PDF に保存」を選ぶと PDF になる |
| 新規 | 2 つの一覧を空にする |

- テキストが同じ `.plan`・`.mylog` は 2 回足しません。`.zip` とフォルダは読みません。
- エラーのある計画書の版は比較と照合から、エラーのあるマイログは集計から外します。
- 作業分析の表の行を押すと、その記録があるマイログのファイル名・行・行の文を下に出します。
- 保存する SVG・PNG には読み込んだ版を埋め込みません。一覧を残すのは `.plans` だけです。
- Chrome と Edge では、開いたファイルにそのまま上書きします。ほかのブラウザでは、ダウンロードとして保存します。
- 一覧と設定は、このブラウザの `localStorage` にも自動で保持されます(どこにも送信されません)。基準日は保持せず、開き直すと今日に戻ります。

## 動作環境

Edge・Chrome などの最近のブラウザで動きます。印刷 / PDF と、図・表の「PDF」は Chrome・Edge で使ってください(Safari では紙の大きさや余白が指定どおりにならないことがあります)。ダウンロードした `index.html` は、ネットに接続しなくても動きます。
